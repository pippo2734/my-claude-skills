# daily-note-evaluator - 識学的日次ノート評価

Obsidianに記録された日々のノート（やったこと、やりたいこと、きづき）を識学の5つの制約に基づいて評価し、改善のためのフィードバックを提供する。

## 発動条件

以下のキーワードが含まれる場合に発動：
- 日報、日次ノート、デイリーノート、daily note
- 評価して、レビューして、フィードバック
- やったこと、やりたいこと、きづき
- 識学的に見て

## 評価フレームワーク（識学の5つの観点）

### 1. 結果（Kekka）評価

**「やったこと」を完全結果/不完全結果で判定**

| 判定 | 基準 |
|------|------|
| 完全結果 | 期限内に100%達成。成果物が明確 |
| 不完全結果 | 「〜した」だけで成果が不明確、「途中まで」「ほぼ完了」など |

**チェックポイント：**
- 「何を」「いつまでに」「どの状態にしたか」が明確か
- 「〜に取り組んだ」「〜を進めた」など曖昧な表現はないか
- 数値や具体的な成果物で表現されているか

### 2. 位置（Ichi）評価

**自分のポジションを意識した記録か**

**チェックポイント：**
- 上司・クライアントの決定に対する批判や愚痴が含まれていないか
- 自分の役割の範囲内で行動しているか
- 「本当は〜すべきだと思う」など越権的な記述はないか

### 3. ルール（Rule）評価

**明確な基準に基づいているか**

**チェックポイント：**
- 「やりたいこと」に明確な期限・条件が設定されているか
- 曖昧な表現（「なるべく」「できれば」「時間があれば」）はないか
- 完了条件が具体的に定義されているか

### 4. 変化（Change）評価

**外部要因ではなく自分の行動にフォーカスしているか**

**チェックポイント：**
- 「〜のせいで」「〜が原因で」など外部帰属がないか
- 失敗・未達成を自分の行動で改善できる視点で捉えているか
- 「きづき」が他者批判ではなく自己改善に向いているか

### 5. 存在（Sonzai）評価

**承認欲求に基づく記述がないか**

**チェックポイント：**
- 「頑張った」「努力した」などプロセス自慢がないか
- 結果ではなく存在を認めてほしい記述がないか
- 「忙しかった」「大変だった」など労いを求める表現がないか

## 入力フォーマット

ユーザーから提供される日次ノートの一般的な形式：

```markdown
## やったこと
- タスクA
- タスクB

## やりたいこと
- 予定1
- 予定2

## きづき
- 気づいたこと
```

※形式は柔軟に対応。「Done」「Todo」「Memo」などの英語表記や、他のセクション名にも対応する。

## 評価例

### 入力例

```markdown
## やったこと
- 企画書を進めた
- ミーティングに参加した
- メールの対応

## やりたいこと
- 企画書を完成させる
- できればジムに行く

## きづき
- 今日も忙しかった。Aさんの資料が遅れて自分の作業も遅れた
```

### 評価例

```markdown
# 識学的評価レポート

## 総合評価
⭐⭐☆☆☆（2/5）

## 各観点の評価

### 結果（Kekka）
**評価**: ❌
**コメント**: 「進めた」「参加した」「対応」は不完全結果。何がどこまで完了したか不明。
**改善例**:
- ❌「企画書を進めた」→ ⭕「企画書の第2章（市場分析）を完成。全体の60%完了」
- ❌「ミーティングに参加した」→ ⭕「週次定例MTGで来週の施策を決定。自分の担当はX施策」

### 位置（Ichi）
**評価**: ⭕
**コメント**: 特に越権的な記述はない。

### ルール（Rule）
**評価**: ❌
**コメント**: 「やりたいこと」に期限がない。「できれば」は識学では禁止ワード。
**改善例**:
- ❌「企画書を完成させる」→ ⭕「明日17時までに企画書を完成させ、上司にレビュー依頼を送る」
- ❌「できればジムに行く」→ ⭕「20時からジムで30分筋トレ」または削除（やらないなら書かない）

### 変化（Change）
**評価**: ❌
**コメント**: 「Aさんの資料が遅れて」は外部帰属。他者のせいにしている。
**改善例**: 「Aさんの資料が遅れる可能性を想定せず、バッファを確保しなかった」

### 存在（Sonzai）
**評価**: △
**コメント**: 「忙しかった」は労いを求める表現。結果で語るべき。

## 識学的リライト提案

### やったこと（修正版）
- 企画書の第2章（市場分析）を完成。全体進捗60%
- 週次定例MTGで来週のX施策を担当することが決定
- クライアント3社からの問い合わせに当日中に回答完了

### やりたいこと（修正版）
- 明日17:00までに企画書を完成させ、上司にレビュー依頼を送る
- 明日20:00にジムで筋トレ30分

### きづき（修正版）
- 他者の作業遅延を想定したバッファ設計ができていなかった。今後は依存タスクがある場合、1日前に進捗確認を入れる
```

## トーン

- **客観的**: 感情を排除し、事実と改善点にフォーカス
- **具体的**: 抽象的な指摘ではなく、具体例と改善例を提示
- **建設的**: 批判で終わらず、識学的な書き方への変換例を必ず提示
